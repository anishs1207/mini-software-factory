# Software factory agents

| Role | Runtime | Primary model | Work |
| --- | --- | --- | --- |
| manager | Hermes | Ollama Cloud `beam` | Read the selected spec, create and assign issues, resolve blocked work |
| builder1 | OpenClaw | Ollama Cloud `beam` | Implement assigned product issues in an isolated worktree |
| builder2 | OpenClaw | Ollama Cloud `beam` | Implement assigned product issues in an isolated worktree |
| reviewer | Hermes | Ollama Cloud `beam` | Review each PR against its issue and spec |
| tester | Hermes | Ollama Cloud `beam` | Execute issue-specific acceptance checks |

No role assumes a particular product. The manager activates a Markdown file created on the VM with `bash agents/start-campaign.sh ./spec.md`; that file is named in every dispatch. The manager creates issues with exactly one `agent:builder1` or `agent:builder2` label for coding work, one `factory:*` stage label, and the active `product:<hash>` campaign label. It links prerequisites with `agents/link-dependency.sh`. One two-minute timer dispatches queued roles. A new spec hash starts a separate campaign after the prior campaign closes.

Builders commit as distinct git authors, push issue branches, and open PRs. Each PR must link its issue, state agent/model/tokens/tests, and include executable `product-check.sh` for GitHub Actions. The queue checks CI before review. Reviewer and tester post verdicts bound to the current head SHA; rejection returns the same PR to its builder. After both pass, `factory-gates` becomes successful and the issue becomes `factory:merge-ready`. The human reviews the PR and GitHub checks, then merges. Dependencies unlock only after blocker issues close and their builder PRs merge. Stale or conflicting branches return to the builder; six builder dispatches end in `factory:blocked` for human inspection. Each dispatch starts a fresh OpenClaw session and can continue up to eight turns or one hour in that session. The Beam slot spaces each turn. Set `FACTORY_MAX_BUILDER_TURNS` and `FACTORY_MAX_BUILDER_SECONDS` to change the bounds. Each turn has its own activity and token record. Repeated malformed tool calls get one bounded follow-up in the same session. Generated dependencies and build output must stay out of PR history.

At builder handoff and before review/test, `agents/verify-pr-authors.py` confirms the local worktree matches the GitHub PR head and every PR-specific commit has the assigned builder's distinct git author name and email. This makes the agent-authored trail visible and rejects mixed human-authored feature commits on agent PRs. Git author metadata can be set by anyone with push access, so it is evidence of process, not cryptographic identity proof.

All roles use Ollama Cloud Beam. Factory model calls share one lock, so the manager chat and queued agents run one at a time. `agents/beam-slot.sh` waits at least 60 seconds after the previous agent run before starting another; set `FACTORY_BEAM_COOLDOWN_SECONDS` to change the gap. This spaces agent runs, while individual model calls inside a run remain controlled by the runtime. Direct unwrapped runtime calls bypass the factory lock. The manager chat releases the lock while waiting for input.

Every dispatched agent run and every interactive manager request writes a private per-run `.activity.json` record under ignored `.local-evidence/usage/`, alongside the runtime's raw usage JSON when available. Records include the agent, issue or task, purpose, model, input/output/total tokens, timestamps, exit code, and retry status. A manager chat request mentioning `#123` is grouped with that issue; an `implement ./spec.md` request is grouped as spec planning. The manager chat resumes its Hermes session between individually metered turns. Run `bash agents/usage-report.sh` on the VM to view individual runs, totals by issue and purpose, and totals by agent/model/phase. To keep an end-of-run snapshot, run `bash agents/usage-report.sh > .local-evidence/usage-summary.tsv`. Unknown token counts stay unknown unless an explicitly documented estimate is added. Run `python3 agents/trace-report.py --output .local-evidence/trace-excerpts.md` for linked handoff and retry excerpts. Use real records in `DELIVERY.md`.

Local preflight verifies the published revision without changing GitHub repository settings. This supports a private repository on GitHub Free. The VM uses the owner's `GH_TOKEN`; GitHub does not enforce PRs, `verify` CI, or `factory-gates` on the unprotected branch. Agents are instructed not to merge, and the human performs the final review and merge, but the shared token can technically merge or push directly. The automatic reviewer product check and product service command run with a clean environment, without inherited agent API keys. These processes still share the VM user account, so treat product code as trusted and do not store product secrets in agent configuration.

For a deployed VM service, a builder implements `product-service.sh` and the manager deploys only merged revisions with `agents/release-product.sh`. For other product types, the spec and manager define the artifact and verification path. Product-specific checks belong in that product's PR and are not part of the general factory gate.
